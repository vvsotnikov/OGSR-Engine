# Explicit whole-map switching policy

## Scope

Whole-map mode now bypasses the five actor-distance gates explicitly through `uses_distance_switching()`, rather than returning `flt_max` as the online/offline thresholds. The normal distance mode retains its thresholds, comparisons and ordering. C++ short-circuit evaluation avoids computing distances at these gates in whole-map mode. This is a small policy simplification, not removal of the registry scan or a demonstrated frame-time improvement.

The changed paths cover dynamic objects, online/offline groups and the older abstract group implementation. Eligibility checks, group representative selection, dead-member cleanup, location synchronization, parent handling, spawn/destruction and registry maintenance retain their existing ordering. Equivalence to the old threshold trick assumes valid finite world positions; this does not add support for corrupt or NaN coordinates.

## Why the scan remains

`CALifeSwitchManager::switch_object` releases redundant objects before/after switching and calls `synchronize_location`. Dynamic-object synchronization updates graph/node positions and graph registries. `CSE_ALifeDynamicObject::try_switch_online` also maintains the offline scheduling registry and client data. `CSE_ALifeGroupAbstract::try_switch_offline` detaches dead members and repairs their registry state inside its member loop. An early return for all online objects would skip required work.

Eligibility is not fully observable through events today. `COMMON_AI/xrServer_Objects_ALife_script.cpp` exposes `m_flags` by mutable reference and graph/node IDs through read/write properties. The flag setters in `xrServer_Objects_ALife.cpp` only change bits; eligibility also depends on `match_configuration()`. Engine creation, load, movement and group code contain direct state writes. Listening only to `CALifeUpdateManager::set_switch_online/offline` would miss changes.

The current level registry already selects the actor's map, and its safe iterator time-budgets traversal after the initial update. The measured inclusive switch zone from previous captures must not be interpreted as entirely removable proximity work.

## Next implementation boundary

1. Separate mandatory location/lifecycle reconciliation from transition-policy evaluation, preserving virtual group behavior and ordering.
2. Add dirty notifications for registration/removal, eligibility/configuration changes, parent/group changes and map membership changes. Reset pending work on load and level changes. Use stable IDs plus a world generation so stale work cannot target a reused ID.
3. Retain reconciliation for raw script mutations until those APIs are instrumented or replaced. Measure that fallback separately; do not describe a hybrid implementation as scan-free.
4. Queue eligible activation requests with a soft per-frame budget. Revalidate object existence, generation, level, parent and eligibility before activation. One spawn may exceed the budget; preserve dependencies and prioritize required actor/script objects.
5. Compare transition/event traces against the existing scanner, then test death, groups, attachment/inventory, save/load, level travel and script flag changes before switching the default.

The existing explicit Lua creation queue is a workload prototype, not this activation queue. This change does not install a new production queue.
