# Review of the whole-map experiment

## Switching behavior

The opt-in policy replaces only the online/offline distance thresholds. All five call sites compare an ordinary computed distance with these thresholds; none squares or multiplies the returned maximum float. Native script eligibility checks precede the distance test in `alife_dynamic_object.cpp` and `alife_online_offline_group.cpp`. Parent handling and the bounded level-registry update loop remain unchanged. `CALifeGraphRegistry::setup_current_level` constructs its registry from the actor's graph level and only adds graph vertices on that level.

This is an eligible-current-map experiment, not a guarantee that every creature will be online. It does not change save serialization. Explicit cross-map travel still invokes switch_offline and graph-registry migration. The Bar lifecycle investigation and persistence checks exercise that path.

No additional gameplay fix follows from this source review. It is not a race-detector audit or a proof covering every script. Activation bursts, campaign timing, scripted encounters, new spawns and combat consequences need further validation. Distance-mode timings versus whole-map timings remain single paired examples on two maps, not a general performance claim.

## Validation harness correction

The original runner waited for a count of snapshots. It could therefore report a completed stage after an ignored command or an unsuccessful map change. The corrected runner requires the command acknowledgement, the engine's save/load success message, and consecutive snapshots on the expected destination. Script/fatal errors, online creatures assigned to another map, duplicate IDs, and known nonzero exit codes fail validation. The offline reader rejects missing fields, empty or truncated snapshots, and ambiguous log selection. The identity comparator refuses absent stages or duplicate keys rather than producing an empty comparison.

Four archived stage logs (save, same-process reload, Garbage, Bar-return) pass the stricter stage checks. The strict reader accepts all 16 complete world snapshots across the two persistence sessions, and the resulting ID/state comparison is unchanged. `Test-ValidationLog.ps1` includes synthetic positive and negative cases for commands, destinations, malformed/incomplete data and error markers. No new playthrough is required for this harness correction.

The temporary diagnostic patch remains unapplied to normal engine sources. Its numbered command-file hook is only in the separate diagnostic binary. The main experiment binary and the manual-playtest binary remain the versions already recorded by hash.

## Remaining review gates

- Natural level-changer round trip, conversation/task hand-in and scripted encounter. The prepared manual launcher uses private save copies and no timed Tracy recording.
- DirectInput initialization failure injection. The guard is implemented and successful initialization has been exercised, but failed COM results have not yet been injected.
- Longer campaign observation to distinguish intended online combat/travel consequences from regressions. New-ID character duplication and all non-creature state are outside the sampled identity checks.

Keep the first pull request a draft until these limits have been considered. Neither this work nor the PR closes the whole-map epic or starts the long-term intelligence implementation.
