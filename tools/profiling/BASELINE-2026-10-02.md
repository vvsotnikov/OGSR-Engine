# Initial baseline and experiment validation

Source baseline: `01faa139995f6afdc66addb48065f053d38f397e`. Original user session: Cordon, 3840x2160, instrumented Release, user reported no noticeable stutters. Original trace and evidence are stored locally at `D:/Games/OGSR-Baseline/captures/2026-10-02-session-01*`.

## Selected loaded-level interval

120–360 seconds relative to engine capture origin was chosen after loading completed at approximately 90 seconds and before shutdown at approximately 392 seconds. This includes in-game UI; it is not a movement-only benchmark. Frame initialization markers and events crossing the interval boundaries were excluded. Results were computed from Tracy's frame and zone data by the tools in this directory.

| Measurement | Result |
| --- | ---: |
| Complete frames | 53,802 |
| Median frame | 4.410 ms |
| p95 frame | 5.166 ms |
| p99 frame | 6.081 ms |
| Maximum frame | 564.799 ms |
| Frames over 50 ms | 7 |
| Mean A-Life switch pass, inclusive | 0.746 ms |
| Mean offline scheduled pass, inclusive | 0.051 ms |
| Mean Lua GC zone | 2.013 ms |
| Mean engine scheduler update, inclusive | 0.260 ms |

The two largest pauses start at 127.33 and 132.32 seconds, coinciding with the two F12 screenshot timestamps (22:58:54 and 22:58:59). Screenshot capture is a plausible contributor; this is timestamp correlation, not complete causal attribution. Other long-frame starts are 188.75, 226.29, 239.48, 261.56 and 317.22 seconds. The last is near a quicksave. These must not all be labelled AI stutters.

Lua GC uses `gc_timeout` with `lua_gctimeout 2000`; its measured mean is consistent with that configured budget. Its worker-thread elapsed time is not automatically critical-path time. A-Life work appears on multiple worker slots across frames, consistent with pool scheduling; the trace does not establish concurrent per-NPC updates.

Two rendering zones recorded 254,364,170 and 248,102,913 events across the full trace. Collector memory reached about 50 GB. Instrumentation overhead remains unquantified. No optimization decision should be based solely on these numbers.

## Runtime validation

- Experimental profiling build compiled successfully; existing upstream warnings remain.
- Pinned CLI tools read the original GUI trace successfully.
- Normal-mode save load and subsequent simulation succeeded. Initial CLI smoke capture caught the loading-screen input gate, so that capture is excluded from gameplay timing comparisons. The launcher now disables this gate in its private settings copy.
- Whole-map mode loaded the same seed save, ran simulation, and saved a 240,032,936-byte trace. The projection tool read it successfully.
- Early normal-mode samples: 89–92 living online server entities. Early whole-map sample: 151 living online and 16 living offline. Counts exclude the actor but may include group representations. Offline entities have not yet been individually classified.
- A short stationary whole-map interval (27–38 seconds) had no frame over 9 ms. This is a smoke-test observation, not a fair performance comparison with the user's moving baseline.
- PowerShell parser checks and `git diff --check` passed.

Further validation: paired routes from the identical save/settings, classify the remaining offline entities, save/reload, level transitions, crowded Bar traversal, and a non-instrumented performance comparison. Whole-map distance bypass is an experiment; epic #1 is not complete.
